# 石化设备智能运维与工单闭环平台（待开发）

> [!warning] 事实边界
> 当前仅为后续候选项目，尚未开发、测试或部署，不属于原石化生产项目的已上线功能，也不得写成现阶段本人已经落地的项目经历。

## 一、产品定位

基于石化设备运维场景独立设计的 Java + AI 扩展项目，把“设备告警 → AI 辅助诊断 → 人工审批 → 工单流转 → 处理复盘 → 知识沉淀”串成可追踪的故障处理闭环。

## 二、计划解决的问题

- 设备告警产生后主要依赖人工判断，排查经验分散在人员、SOP 和历史工单中。
- 重复告警容易产生重复工单，缺少统一的告警聚合、幂等与状态追踪。
- 故障处理结果没有结构化回填，类似问题再次发生时仍需重复排查。
- AI 只能提供建议，创建、派发、关闭工单及高风险操作必须保留人工审批。

## 三、候选功能范围

1. **告警中心**：告警去重、聚合、恢复、等级、超时与重复建单幂等。
2. **工单中心**：待确认、待派单、待接单、处理中、待验收、已完成/已驳回状态机。
3. **AI 故障诊断**：RAG 检索设备手册、维修 SOP 和历史案例；Tool Calling 查询设备、心跳、告警与维修记录。
4. **人工审批**：AI 生成诊断建议和工单草稿，关键状态变更由人工确认。
5. **知识闭环**：工单完成后生成故障复盘草稿，经审核后写入故障知识库。
6. **可观测与审计**：记录 traceId、检索来源、工具参数、调用结果、审批人与状态变化。

## 四、候选技术栈

- Java、Spring Boot、Spring Cloud Alibaba、Spring AI
- MySQL、Redis、RabbitMQ、XXL-Job
- Milvus、Embedding、Reranker、RAG
- SSE / WebSocket、Function Calling，后续评估 MCP 接入
