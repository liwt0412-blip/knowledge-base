# 失效分析 V1\.2 本体平台业务接口设

# 失效分析 V1\.2 本体平台业务接口设计

## 文档目的

本文只说明失效分析系统与本体平台之间需要对接的业务接口，并回答五个问题：

1. 本体平台向失效分析应用提供哪些接口。

2. 失效分析应用向本体平台提供哪些接口。

3. 每个智能体运行时需要读取和返回哪些业务数据。

4. 分析步骤如何异步推理、追踪并交给失效分析应用继续编辑、保存和审批。

5. 平台拆分后，分析步骤示例图片、失效案例及文献清单、全文检索与文件内容如何跨平台访问。

接口根地址：

```Plain Text
本体平台：{ontologyBaseUrl}/open-api
失效分析系统：{businessBaseUrl}/open-api/ontology
```

增加环节 8 分析过程简报和推理信息补充两个只读查询接口后，双方目标共对接 **20 个接口**：

- 本体平台提供 18 个接口，由失效分析应用调用。

- 失效分析应用提供 2 个接口，由本体平台调用。

## 双向接口总览

### 2\.1 失效分析应用调用本体平台

第 1～15 项属于失效分析应用调用本体平台的 Agent 及配套接口：应用可直接调用，不传 Token、`Authorization`、Service Token、`tenant-id` 或其他租户头；本体平台在这些接口内部固定使用 `tenantId=1`。第 13、14 项只读取 REPORT\_DRAFT 的同版本推理支撑产物，不创建新的 AI 任务。分析过程简报内部的发现或规则反馈由失效分析应用自行处理，不调用第 15 项。

第 16～18 项数据检索接口同样不传 Token，但与第 1～15 项固定内部租户的方式不同：失效分析应用后端必须统一传 `tenant-id: 1` 和正整数 `X-User-Id`；本体平台只允许租户 1，并按第 4\.10 节解析绑定领域和当前发布范围。

### 2\.2 本体平台调用失效分析应用

报告智能校审的完整报告和 referenceData 已随启动请求提交，本体平台不为该能力反向调用上述两个接口。

本节反向业务接口不适用前述免租户规则。本体平台调用失效分析应用时完全遵循对方现有契约：继续传 `tenant-id: 1`，不传 Token；对方后续调整时再按其新契约变更。

### 2\.3 智能体与业务输入对应关系

能力专属工作流与正式推理子链

每个 Agent 绑定自己的已发布工作流，按需选择业务接口取数、事实生产、正式推理、知识检索、模型生成、组装或校审节点，不存在所有 Agent 统一执行的固定流程。只有工作流声明正式推理时，该能力冻结的原始输入才进入“清洗与事实生产 → 标准事实批次 → 冻结推理模式 → EvidencePack”受治理子链；其中只有 `OWL_RULE_HYBRID` 生成 Runtime ABox 并执行 OWL。任何节点都不得把接口响应、公开流程输出或历史报告直接当成正式推理事实。

REPORT\_GENERATION 当前绑定

当前改造只把“真实任务上下文 BUSINESS\_OPERATION → 标准事实生产 → 正式推理 → 报告组装”绑定到 REPORT\_GENERATION 的精确工作流版本。是否使用标准事实和正式推理由每个 Agent 自己的工作流决定，不能从能力类型或相邻流程自动继承。

正式推理模式归属

Agent 的外层工作流只决定是否调用平台正式推理能力；Java 正式推理内部步骤不作为 Python 可自由选择的外层 Tool。调用正式推理时，工作流发布版本必须冻结 `RULE_ONLY` 或 `OWL_RULE_HYBRID`，运行中不得切换，也不得把固定八步计划施加给所有 Agent。

## 公共协议

### 3\.1 请求头

第 4\.1～4\.9 节本体平台 Agent 及配套接口不执行 Token、`Authorization` 或 Service Token 认证，失效分析应用可直接调用；调用方维度由接口路由固定为失效分析应用，租户由接收接口内部固定为 `tenantId=1`。这些接口必须部署在内网、VPN 或网关网络白名单之后，不得暴露到不受信网络；`operatorId` 和 `X-Request-Id` 只用于业务操作与链路追踪，不是认证凭据。

第 4\.10 节数据检索不校验 Token，统一要求请求头 `tenant-id: 1` 和正整数 `X-User-Id`。`X-User-Id` 只表示调用方声明的业务操作人，不是认证凭据；三个接口仅允许租户 1，并必须部署在受信内网。第 5 节反向业务接口按失效分析应用现有契约调用，继续传 `tenant-id: 1`、不传 Token。

异步启动接口按“能力类型 \+ X\-Request\-Id”识别同一次请求：

- 请求载荷摘要一致时返回原 aiTaskId，不重复创建生成任务。

- 请求载荷摘要不一致时返回 HTTP 409、errorType=REQUEST\_CONFLICT。

- 用户主动重新生成必须使用新的 X\-Request\-Id，从当前业务数据冻结新快照。

### 3\.2 统一成功响应

除 SSE 外，双方所有 JSON 成功响应均使用以下完整结构。没有额外业务数据时 data 返回 \{\}：

```JSON
{
  "code": 0,
  "msg": "操作成功",
  "data": {}
}
```

### 3\.3 统一失败响应

```JSON
{
  "code": 400,
  "msg": "参数校验失败",
  "data": {
    "errorType": "INVALID_PARAMETER",
    "details": []
  }
}
```

### 3\.4 异步任务统一调用方式

分析步骤生成、初步结论小型报告、最终候选报告、报告智能校审和抗失效准则候选统一采用异步接口协议。内容优化为同步调用，报告质量 Prompt 片段为同步发布。

异步启动成功响应：

```JSON
{
  "code": 0,
  "msg": "任务已受理",
  "data": {
    "aiTaskId": "task_01JABC"
  }
}
```

异步启动成功时 HTTP 状态码为 202。分析步骤生成可以额外返回完整阶段、步骤和子项完成事件；初步结论小型报告和最终候选报告可以额外返回完整章节事件。所有最终业务结果只通过第 4\.7 节结果接口返回。

分析步骤生成不使用 BLOCKED：必要输入不足时任务进入 FAILED，failure\.errorType=INPUT\_INSUFFICIENT；输入完整但无规则命中时任务进入 COMPLETED，并通过结果接口返回 generationStatus=NO\_MATCH、steps=\[\]。

BLOCKED 是其他适用能力的终态审计记录，不提供继续或恢复操作。调用方补齐业务数据后，必须使用新的 X\-Request\-Id 发起新任务并冻结新快照。

REPORT\_REVIEW 采用原子完成语义：只有确定性校验、正式推理、AI 语义校审、Java 结果校验、结果正文与 EvidencePack 全部成功持久化后，任务才进入 COMPLETED 并返回 resultId。任一阶段失败，任务进入 FAILED，不生成 resultId，不保存或暴露部分校审结果。

本期不定义异步任务、事件、业务快照、Prompt 片段版本、结果和 EvidencePack 的 TTL、过期时间或自动删除任务；接口不返回 expiresAt。后续确需归档或删除时，另行设计保留策略、迁移和审计规则。

REPORT\_DRAFT 采用扩展原子完成语义：候选报告、EvidencePack、分析过程简报、ADVISORY 推理信息补充和终态事件全部成功持久化后才能进入 COMPLETED。任一部分失败时任务进入 FAILED，不生成或暴露 resultId。分析过程简报和补充项是同一报告结果的只读子资源，不是新的异步任务。

## 本体平台提供的接口

### 4\.1 字段内容优化

提供方：本体平台。调用方：失效分析应用。

作用：在不改变事实、数值、单位、不确定性、已有符合性判断和技术结论的前提下，依据失效分析领域发布中的字段族策略和术语投影优化单个业务文本字段。调用方式：同步 POST。

```HTTP
POST {ontologyBaseUrl}/open-api/ai/v1/content-refinements
```

动态子项请求示例：

```JSON
{
  "operatorId": "10086",
  "fieldCode": "MACRO_ITEM_CONCLUSION",
  "itemName": "断口宏观形貌分析",
  "originalText": "裂纹从外表面开始，往里面扩展"
}
```

固定字段请求示例：

```JSON
{
  "operatorId": "10086",
  "fieldCode": "IMPACT_DESCRIPTION",
  "originalText": "造成生产停滞，部分零件报废"
}
```

调用范围：

动态子项规则：

- 上表定义 16 类稳定字段族，不定义页面实例数量。

- `MACRO_ITEM_CONCLUSION`、`MICRO_ITEM_CONCLUSION`、`COMPLIANCE_TEST_RECORD`、`REPRODUCTION_METHOD`、`REPRODUCTION_OBSERVATION`、`REPRODUCTION_ITEM_CONCLUSION` 属于动态字段族，调用时可传页面已有的 `itemName`。

- 动态子项可以由方案或业务配置任意新增、删除、改名和排序；本体平台不穷举子项名称，不按名称建立提示词映射，也不要求人工逐项配置。

- 同一动态字段族的所有实例复用同一 `fieldCode` 及字段族策略。运行时仅把 `itemName` 作为当前文本所属主题的数据上下文，不把它当成指令或事实来源。

- 当前案例页面共 58 个优化入口仅用于联调覆盖，不得把子项序号、步骤序号或业务行 ID 拼入 `fieldCode`。

- 应用方持有动态子项实例及回填位置；本体平台不需要业务行 ID。

提示词与示例规则：

```Plain Text
fieldCode
  -> 选择发布态字段族策略（允许操作、推荐结构、禁止新增项、术语策略、固定示例）
itemName（可选，动态字段建议传）
  -> 已传时注入“当前子项名称”数据槽；未传时跳过该数据槽，均不选择提示词
originalText
  -> 注入待优化原文数据槽
```

- 原型中的“示例：导致生产停滞 / 造成报废损失”等内容，作为字段族策略中的固定表达示例管理，不由应用方每次传入。

- 示例只说明该字段允许的表达类型和风格，不是当前业务事实；模型不得把原文中不存在的示例内容写入候选。

- 不存在也不接收 `fieldContext.itemRequirement`。动态子项没有逐项提示词配置需求；字段差异由 `fieldCode` 对应的字段族策略解决。

调用边界：

- 空值由失效分析应用拦截，不调用本接口。

- 外部请求包含三个必填业务字段，可选增加 `itemName`；不传 taskId、动态子项 ID、domainCode、DomainRelease、术语版本、Prompt、工作流坐标、示例或自由文本要求。

- `itemName` 在传入时必须按普通数据处理，不得解释为 Prompt 指令，也不得作为新增检测结果、标准、参数或结论的依据。

- 本体平台 Java 根据能力绑定冻结失效分析 DomainRelease、字段族策略、提示词版本、输出 Schema 和守卫策略；字段启用术语规范化时，再解析固定词法投影。

- 字段族策略和原文确定性守卫是所有字段的必需基线；术语是按字段启用的可选增强。

- 本接口不查询、不绑定、不消费标准事实模型。标准事实模型属于结构化事实抽取、事实校验和正式推理链路，不属于文本润色链路。

- 候选必须保持与 `originalText` 相同的主要语言，不得翻译，不得新增原因、责任、检测结果、标准、参数、符合性结论或复现判断。

- 结构化阈值、实测值、枚举判定不调用本接口；它们由失效分析应用按自身业务规则保存和校验。

- 环节 2 方案生成、环节 6 初步结论生成、环节 8 报告生成、环节 9 报告校对、环节 10 抗失效准则生成使用各自独立接口，不复用本接口。

发布态工作流：

```Plain Text
START
  -> resolve_refinement_context (BUSINESS_OPERATION)
  -> generate_candidate (AI_GENERATE)
  -> validate_and_commit_candidate (BUSINESS_OPERATION)
  -> END
```

其中 `resolve_refinement_context` 按 `fieldCode` 组装必需字段族策略和固定示例，动态字段且请求已传值时再加入 `itemName` 数据槽，并按策略解析可选术语；`validate_and_commit_candidate` 对候选执行原文确定性守卫和已启用的术语附加守卫，并保存本体平台候选结果。两者均复用现有 `BUSINESS_OPERATION` 组件，不新增工作流组件类型。

语义上下文处理规则：

实际启用的术语约束仅进入本体平台运行审计，不扩展外部请求，也不要求失效分析应用处理新的成功响应字段。

成功响应：

```JSON
{
  "code": 0,
  "msg": "内容优化完成",
  "data": {
    "candidateText": "裂纹起始于外表面，并向内部扩展。"
  }
}
```

模型失败、必需上下文缺失或守卫失败不得返回未验证候选。

### 4\.2 智能体业务接口

#### 4\.2\.1 失效分析方案生成

作用：根据失效分析应用提供的当前任务背景启动分析步骤推理。调用方式：异步 POST，成功受理时返回 HTTP 202；最终步骤结果通过第 4\.7 节查询。

```HTTP
POST {ontologyBaseUrl}/open-api/ai/v1/analysis-plan-generations
X-Request-Id: 8f9f8db8-85c4-4e6b-93e0-f5eb6ea183af
Content-Type: application/json
```

请求：

```JSON
{
  "operatorId": "10086",
  "taskId": "2026-04-SXFX-005"
}
```

`X-Request-Id` 为必填幂等键。同一调用方、能力、请求键和相同请求载荷的网络重试返回原 `aiTaskId`；不同载荷复用同一键返回 HTTP 409、`REQUEST_CONFLICT`。用户主动“重新生成”时必须使用新的 `X-Request-Id`，本体平台重新读取业务上下文并创建新的推理任务。

成功受理响应：

```JSON
{
  "code": 0,
  "msg": "任务已受理",
  "data": {
    "aiTaskId": "task_plan_01JABC"
  }
}
```

本体平台运行边界：

1. 按 `taskId` 调用第 5\.1 节任务上下文接口，只读取并冻结当前 `background`。

2. 通用必要输入为任务标题或故障现象描述、故障对象或部位；缺失时任务进入 FAILED，`failure.errorType=INPUT_INSUFFICIENT`。

3. 正式规则直接推导适用的分析步骤定义；不读取固定基础方案，不复用业务当前方案，也不读取旧待补充项、人工编辑和审批结果。

4. 确定性组装器按冻结的步骤应用模板补齐步骤名称、顺序、执行子项和父步骤示例图片资源。模型不得自由新增、删除或重排步骤拓扑。

5. 输入完整但没有规则命中时任务正常完成，最终结果为 `generationStatus=NO_MATCH`、`steps=[]`。

6. 本能力不生成分析过程简报、待补充项、候选方案、生成批次或业务当前方案，不向业务应用写入任何方案状态。

7. 进度通过第 4\.5 节 SSE 返回完整阶段、步骤和子项完成事件；最终结果结构见第 6\.1 节。

规则资产重整边界（2026\-09\-01 确认）：

1. V7 来源批次的 162 条旧初始化资产全部按既定清理策略退役，不以旧 `PUBLISHED/PENDING` 记录作为可执行规则证明。

2. `core-v1.3-draft.owl` 仅作为规则迁移来源，不作为本接口运行时读取的 OWL 制品；运行仍冻结 DomainRelease 中的正式 OntologyPublication、StandardFactBatch 和 RuleVersion。

3. 35 条原 `OPTIONAL_TRIGGER_INCOMPLETE` 分为：8 条恢复结构化 `PushTriggerRule`，23 条复用已有受控特征并补标准事实映射，4 条补最小 TBox/标准事实谓词。

4. 8 条旧“字段 \+ 关键词 \+ CONTAINS”声明迁移时必须绑定当前标准事实坐标；规则节点不得自行重新读取业务接口或扫描未治理的原始长文本。

5. 23 条涉及图片、现场描述或背景文本的观测特征，由既定受控抽取/事实生产节点生成候选并由 Java 治理校验；规则中心只消费冻结后的结构化事实。

6. 4 条只补“相邻腐蚀产物转移”和“介质浓度/暴露时长/特殊元素暴露”两组共享语义，不新增通用函数中心或领域专用规则算子。

7. 所有重建规则默认未启用；只有 canonical AST 编译通过、缺失事实返回 `UNKNOWN`、真实任务回放符合预期后，才允许形成活动版本。

8. 精确清单见 失效分析 V7 规则中心准入与待补规则清单。\#\#\#\# 4\.2\.2 初步结论生成
 作用：为环节 6“编制失效分析初步结论”生成一份可供人工采纳和编辑的小型报告候选。小型报告与最终候选报告采用相同的五段正文结构和生成约束，但只使用截至环节 5 的冻结业务输入，分析结论必须明确为初步结论。调用方式：异步 POST。

本接口生成“初步结论候选”，不直接创建或覆盖失效分析应用中的草稿、定稿和审批状态。

##### 启动请求

```HTTP
POST {ontologyBaseUrl}/open-api/ai/v1/preliminary-conclusion-generations
Content-Type: application/json
X-Request-Id: 2026-04-SXFX-005-preliminary-001
```

```JSON
{
  "operatorId": "10086",
  "taskId": "2026-04-SXFX-005"
}
```

X\-Request\-Id 为必填幂等键。同一调用方、同一能力和同一 X\-Request\-Id 对应的请求载荷摘要一致时返回原 aiTaskId；摘要不一致时返回 HTTP 409、REQUEST\_CONFLICT。用户主动重新生成必须使用新的 X\-Request\-Id。

##### 本体平台读取并冻结的业务输入

启动请求不重复传入整份业务数据。本体平台根据 taskId 调用第 5\.1 节任务上下文接口：

```HTTP
GET {businessBaseUrl}/open-api/ontology/v1/tasks/{taskId}/context?include=background,plan,analysisResults,supplementSubmissions
```

本体平台在任务受理后冻结规范化输入、图片引用、正式推理范围和版本信息，并计算业务快照摘要。后续业务数据变化不影响当前任务。

projectName、clientName、reporterName 或 reviewerName 暂无数据时，在候选正文中显示“待补充”，不得要求模型猜测。

以下核心输入不足时，任务进入 BLOCKED，不生成部分候选：

- 任务标题或故障现象缺失；

- 故障对象或部位无法识别；

- 环节 3 至环节 5 没有可用于形成初步结论的已保存分析结论；

- reportUse=1 的图片引用存在，但任务归属、文件元数据或图片内容无法校验。

#### 4\.2\.3\.1 查询分析过程简报


本体关系列仅用于展示。ontologyEvidence 只返回实体、规则和关系的业务名称、类型及说明；实体和规则的来源使用可直接展示的 sourceLabels:string\[\]，例如 \["报告知识","文献知识"\]，按首次证据出现顺序去重；关系暂不返回来源字段。公开结果不返回 sourceCategory 编码。公开字段不得返回实体 ID、规则 ID、ruleCode、规则包版本或内部 IRI，也不提供详情跳转或新增跳转接口。Java 投影时在步骤内按规范化实体 IRI 去重实体，按本次冻结规则包内 ruleCode 去重规则，按 sourceIRI \+ predicateIRI \+ targetIRI 去重关系；跨规则包审计身份使用 rulePackageVersion \+ ruleCode。多条证明路径仍完整保存在 EvidencePack。

启动接口不再反向调用第 5\.2 节查询报告，也不接收 Prompt、模型、工作流、规则明细或 EvidencePack。调用方提交的内容只作为待校审输入；报告质量指令来自提示词治理模块的已发布片段。

输入安全边界：

1. HTTP 请求体按 UTF\-8 计不超过 10 MiB，其中 report\.contentHtml 不超过 5 MiB。

2. contentHtml 为空、净化后无有效正文或包含无法安全移除的主动内容时，同步返回 HTTP 422、errorType=INVALID\_REPORT\_CONTENT。

3. 请求体超限时同步返回 HTTP 413、errorType=REPORT\_REVIEW\_PAYLOAD\_TOO\_LARGE，不创建 aiTaskId。

4. 字段缺失、类型错误、未知字段或 taskId/reportId 组合不合法时同步返回 HTTP 400、errorType=INVALID\_PARAMETER。

5. referenceData Schema 合法但事实内容不足，或当前不存在可用报告质量 Prompt 片段时，仍返回 HTTP 202 和 aiTaskId，任务立即进入 BLOCKED 并记录 pendingItems。

6. BLOCKED 是终态审计记录；补齐输入或发布可用片段后使用新的 X\-Request\-Id 重新启动，不在原任务上追加或覆盖快照。

成功受理：HTTP 202，响应格式与第 3\.4 节一致，仅返回 aiTaskId。完成后通过第 4\.7 节查询结果，resultType=REPORT\_REVIEW，resultData 结构见第 6\.4 节。校审结果是可审计的候选建议，不直接修改报告。

任务状态 BLOCKED 只表示完整报告、事实依据或报告质量 Prompt 片段不足，不能生成有效校审结果；校审业务结论不使用 BLOCKED。

#### 4\.2\.5 抗失效准则候选生成

作用：根据指定终版报告、完整分析方案和任务上下文生成抗失效准则候选。调用方式：异步 POST。

```HTTP
POST {ontologyBaseUrl}/open-api/ai/v1/prevention-guideline-generations
```

```JSON
{
  "operatorId": "10086",
  "taskId": "2026-04-SXFX-005",
  "reportId": "report_01JDEF"
}
```

受理流程：

1. Java 公共启动接口校验请求字段和 `X-Request-Id`，按第 3\.1 节使用固定调用应用及 `tenantId=1` 执行幂等检查；不校验 Token、`Authorization` 或租户请求头。校验通过即创建任务并返回 HTTP 202 与 `aiTaskId`。

2. 异步工作流启动后，通过受治理业务操作调用第 5\.1 节，一次性读取 `background、plan、analysisResults、conclusions、supplementSubmissions`，再调用第 5\.2 节读取 `reportId` 对应的指定终版报告。

3. 失效分析应用负责校验任务与报告归属、报告正文以及环节 9 签署状态；异步工作流把业务输入问题转换为 `BLOCKED`，把业务服务或技术异常转换为 `FAILED`。

4. 业务输入校验通过后，本体平台冻结完整业务上下文和完整报告，并把快照坐标绑定到当前 `aiTaskId`。

5. 异步工作流从 `plan.template` 中识别环节 2 梳理参考，从指定报告和任务上下文中抽取失效原因及支撑事实；业务应用不新增准则专用投影字段。

启动请求不传准则维度、条目、附件、Prompt、规则、工作流参数或业务报告正文。

受理后的任务状态约定：

- 业务任务或报告不存在、报告归属不符、报告未完成环节 9 签署、正文为空，或冻结输入中无法抽取出足以支撑准则的失效原因时，任务进入 `BLOCKED` 并返回 `pendingItems`；原任务不恢复，业务数据补齐后使用新的 `X-Request-Id` 重新启动。

- 输入充分但没有可安全给出的准则候选时，任务正常 `COMPLETED`，结果返回 `items=[]`。

- 失效分析应用暂不可用、返回无法解析的响应，或工作流、模型和内部服务发生技术异常时，任务进入 `FAILED`，不得生成占位候选；可重试性通过通用 `failure.retryable` 表达。

- 正式推理或相似案例检索未启用、未命中时不得阻断任务；一旦采用其结果，必须在内部 EvidencePack 或来源记录中保留证据。

成功受理：HTTP 202，响应格式与第 3\.4 节一致，仅返回 aiTaskId。完成后通过第 4\.7 节查询结果，resultType=PREVENTION\_GUIDELINE，resultData 结构见第 6\.5 节。

#### 5\.1\.2 步骤补充文本的重新推理规则

supplementSubmissions 是业务人员围绕检查项保存的自由文本，不是已经验证的正式事实，也不是仅供模型阅读的旁路 Prompt。

本体平台每次报告生成或重新生成都必须：

1. 与其他业务数据一起重新读取全部 supplementSubmissions。

2. 规范化并冻结原文、步骤坐标和来源。

3. 将可确定性映射的数据直接形成 BUSINESS\_SUPPLEMENT 来源事实。

4. 将需要抽取的自由文本先形成 CandidateFact，再经 Java Schema、数据类型、单位、枚举、来源和冲突校验。

5. 通过校验的事实进入 StandardFactBatch，并按工作流冻结的正式推理模式进入规则\-only 或 OWL 混合推理，最终形成 EvidencePack；只有混合模式生成 Runtime ABox。

6. 与既有正式事实冲突时产生 REQUIRED 缺口，不得静默覆盖。

7. 无法形成正式事实但可以安全作为背景的文本只支持候选叙述，并保留来源标识。

8. 无法安全使用的内容继续形成推理信息补充项。

失效分析应用负责保存补充原文和完成状态；本体平台只在运行快照中保存不可变证据副本，不提供补充内容写接口。

1～500 字；该限制同时进入模型输出 Schema、Java 准入校验和公开结果 Schema，处理后为空或越界时不得截断、合并或自动修复，统一以 `RESULT_SCHEMA_INVALID` 失败。完整简报包含本次运行纳入分析的全部 plan\.template\[\] 步骤；ontologyEvidence 的实体和规则来源返回可直接展示的 sourceLabels:string\[\]，按首次证据出现顺序去重；关系暂不返回来源字段，且不返回 sourceCategory 编码；实体按内部 IRI 去重，规则按冻结规则包内 ruleCode 去重，关系按 sourceIRI \+ predicateIRI \+ targetIRI 去重，公开结果不暴露这些内部键；没有主要发现的步骤仍返回 findings=\[\]。每个步骤固定返回 stepCode、stepOrder、stepName、analysisPurpose、findings、imageRefs、ontologyEvidence 和 references；无数据时 findings、imageRefs、references 返回 \[\]，ontologyEvidence 返回 \{entities:\[\], rules:\[\], relations:\[\]\}，不得省略或返回 null；stepCode 直接引用本次冻结 plan\.template\[\]\.uniqueCode，不使用 associatedAction 代替；stepName 原样返回本次冻结的 plan\.template\[\]\.name，模型不得改写；analysisPurpose 根据步骤名称和检查项内容受约束概括，无可用检查项时回退为步骤名称；findings 为主要发现或观察结果的 string\[\]。简报 imageRefs 返回本次运行冻结的 analysisResults\.items\[\]\.files 全部文件引用，不受 reportUse 限制；报告 docSegments\[\]\.imageRefs 和 HTML 只使用 reportUse=1。简报图片先按所属检查项 sort、再按输入文件 sort 展开，并将公开 sort 在步骤内重新编号为 1\.\.N，不返回 subStepCode。两者均使用稳定 fileRef，并返回 fileName、title、description 和 sort；不返回输入字段名 fileDataId、业务存储 fileId 或文件 URL。references 返回 documentId、title、fileName 和可空 pageNo；同一步骤内按 documentId \+ pageNo 去重并按首次引用顺序返回，同一文档不同页分别保留，跨步骤不去重。应用通过现有文档内容接口打开原文，不返回文件 URL。

推理信息补充按 stepCode \+ subStepCode 汇总，同一检查项最多一条；每项只返回 stepCode、必填的 subStepCode、missingContent 和 supplementGuide，不返回 itemId、severity 或 inputMode。本体平台不返回或维护 submitted、userComment、submitter、completedAt。

REPORT\_DRAFT 使用生成时的最新冻结输入，包含环节 7 和业务侧已保存的 supplementSubmissions；排除 conclusions\.preliminaryConclusion 和 conclusions\.finalConclusion。补充文本必须重新经过事实映射、正式推理和 EvidencePack 生成，不能只追加给模型。

SSE 的 section\_completed 仅用于生成期间按章节增量预览。任务完成后，应用必须以本结果的 doc 和 docSegments 整体替换临时预览，然后固定查询两个推理支撑子资源；无补充项时 reasoning\-supplements 返回 items=\[\]。

REPORT\_DRAFT 不公开章节 evidenceRefs；章节与完整 EvidencePack 的证据关联只在本体内部保存。候选报告、EvidencePack、分析过程简报和推理信息补充采用原子完成语义。任一校验或持久化失败时不产生可读 resultId。

本体平台不生成封面、页眉、页脚、DOCX、PDF 或报告级 fileName。用户采用、编辑、排版、文件解析、反馈、导出和正式保存由失效分析应用负责。

职责口径：ontology\-ai 编排节点并行生成报告章节候选和一份批量简报叙述候选，再调用 Java `assemble-report`；Java 将 `reportUse=1` 文件映射为授权 `fileRef`，校验简报内部 `stepCode/evidenceRefs`，执行 HTML 安全净化，并确定性组装报告、完整简报和推理信息补充。Java 不调用模型改写事实和结论。

本期 REPORT\_DRAFT 不附带质量评分、审核结论、审核意见或修复记录。候选语义和文字质量留给后续业务流程处理；硬校验失败的候选不形成可查询结果。
