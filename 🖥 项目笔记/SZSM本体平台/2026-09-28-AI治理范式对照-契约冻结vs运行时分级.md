## 0. 一句话

同一个命题——**怎么把 AI 的不可控性关进工程笼子**——存在两种正交解法：

- **路径 A（契约冻结）**：事前把流程编译成不可变契约，执行侧只能照单执行
- **路径 B（运行时分级）**：事中对每个动作分级裁决，用物理隔离兜住越界

一个管「**这个流程能不能跑**」，一个管「**这一刻这个动作该不该放行**」。

---

## 1. 命题本身

让 AI 真正干活，就必须给它工具、文件和终端。于是出现一个新问题：

> 它没被授权时，出于"聪明"绕过了限制怎么办？提示词注入让它执行了危险命令怎么办？
> 它把数据发到了不该发的地方怎么办？

传统做法是加权限校验。但 AI 系统的特殊之处在于：
**威胁不来自代码漏洞，来自"合法能力被误导性使用"**——所以治理不能是插件，必须是架构。

两种路径，分别在两个不同时间点上锁。

---

## 2. 路径 A：编译期契约冻结（本项目）

**【已读源码】**

机制：

| 环节 | 做法 |
|---|---|
| 权威归属 | 控制面（Java）编译并**冻结**工作流、ToolPlan、工具白名单、权限与发布版本 |
| 执行侧约束 | 执行侧（Python）只按冻结契约执行，**不接管权限、业务主数据、正式推理权威** |
| 冻结身份 | 请求携带冻结的版本 / 策略 / 摘要；配置变更**不静默影响在途任务**，历史任务不重解释 |
| 身份发号 | 执行侧产出稳定 `localRef`，**最终 chunkId / 索引版本由控制面生成** |
| 跨语言访问 | 控制面下发**短期预签名票据**，执行侧不持有长期凭据（票据过期即 403） |
| 幂等 | 任务 revision 级稳定幂等键；已完成的同一请求重提**不产生额外外部调用** |
| 降级 | 可降级项（网关不可用/超时/引擎失败）投影为**带固定 `degradationCode`** 的空结果并继续；`strictMode=true` 失败关闭 |
| 降级禁区 | **配置、可信上下文、权限、版本及发布治理拒绝——一律不允许降级** |
| 质量准入 | 门禁三级 PASS / REVIEW_REQUIRED / ERROR；准入例外**绑定产物版本**，旧快照不续用 |

一句话概括：**执行权下放，身份权与治理权上收。**

## 3. 路径 B：运行期分级裁决 + 物理隔离（开源项目研究）

**【来源：公开仓库 README / docs/approval-guidance.md / docs/openshell.md / coworker/risk.py】**

### 3.1 五级风险分类（声明式，非硬编码）

`risk.py` 的演进自白：**风险从"权限引擎里内联硬编码的工具名集合"变成"声明的属性"**，
由一个 `classify` 函数统一读取。

| 风险类 | 含义 | 门控方式 |
|---|---|---|
| READ | 无副作用 | 永远允许 |
| EGRESS | 触网——**请求本身就能把数据带出去** | 域名白名单 + 具名审批卡 |
| WRITE_LOCAL | 改工作区 | 路径范围 + 模式门控 |
| EXEC | 跑命令 | 模式门控 |
| EXTERNAL | 机器外的副作用 | 无人值守时的停靠钩子 |

严格度表：EXEC 与 WRITE_LOCAL 并列最高（注释称"皇冠上的宝石"）。

### 3.2 覆盖只能收紧，不能放松

用户配置可以**放松**普通插件工具（让过度谨慎的插件安静点），
但对**有底线的工具只能收紧**——判定方式是严格度比较：

```
if base is None or _STRICTNESS[ov] >= _STRICTNESS[base]: return ov
# 对"有底线的工具"，放松型覆盖一律忽略
```

原因写得直白：**把 write 降级成 read，会一步同时关掉路径范围和只读门禁。**

### 3.3 三道硬底线（floor）

| 底线 | 覆盖对象 | 理由 |
|---|---|---|
| 内置写 / 执行 / 出站 | 按名字固定 | 一旦可放松，等于关掉整套门控 |
| 连接器目录写 | 由目录权威记录判定 | 放松会导致**一步同时关掉**审批卡、审查器、只读模式 |
| **第三方 MCP 工具** | **永远 EXTERNAL，焊死** | 「分不清它的 read 是真读，还是**披着 read 名字的 write**」 |

第三条附带一个精彩的信任判定法：**按"来源"判定，不按"名字"判定**。
第一方 MCP 连接器也长 `mcp__*` 的样子，但它们在接线时被重新标记为 `category="connector"`，
因为其读写类型有**第一手权威记录**。这样同时堵住了两个方向：

- 第一方的工具不该被无关底线误伤
- **自定义 server 即使复用了目录里的名字，仍然带 `category="mcp"`，照样落底线上**

### 3.4 审查者模型（auto-approve）

- 作者可提供**最多 2400 字符**的审批指引，与系统提示词**分开**
- 指引必须写"正常工作 + 明确边界"，**不接受"批准一切"**
- 指引**只影响模型判断**：不授予工具/连接器权限、不绕过任何硬底线、不覆盖用户限制
- **序列化请求超 64,000 字符 → 结论是「不确定，需要人类」，而不是静默截断**
- 上下文变更会**作废**待处理的审查结论
- 「历史 agent 转向**不算**人类授权」；lead 的建议**只是建议，不当许可**
- 反复被拒绝 → **熔断器暂停审查者**，控制权交回人
- 文档明确承认：**审查者的判决是判断，不是保证**——真正兜底的是硬底线 + 审计链

### 3.5 沙箱（物理隔离）

| 原则 | 原文表述 |
|---|---|
| 密钥 | **「Secrets are absent, not denied.」**（是不存在，不是被拒绝） |
| 墙的执行者 | **「由容器强制，不是由模型强制」** |
| 沙箱内运行器 | **本身不可信**：不持有密钥、不做决定、返回的一切当作数据 |
| 审计来源 | 来自**墙外**（应用侧工具调用事件 + 沙箱自身日志） |
| 失败姿态 | 沙箱不可用时**拒绝会话，绝不无保护运行** |
| 内核要求 | Landlock 是硬要求，缺失则**拒绝运行**而非裸奔 |
| 网络 | 允许列表（默认仅代码托管与包仓库；严格/标准两档） |
| 工具实现 | 工具**定义**留在外面，**执行**在沙箱内由重新实现的 runner 承担 |
| 凭据授予 | 默认全关；按需**复制**指定文件进私有 home，随沙箱销毁；真实文件从不以写模式打开 |

## 4. 逐维对照

| 维度 | 路径 A：契约冻结 | 路径 B：运行时分级 |
|---|---|---|
| 裁决时机 | 编译期（发布时冻结） | 运行期（每次动作） |
| 治理对象 | 流程 / 工具计划 / 白名单 / 版本 | 单次工具调用的风险类别 |
| 权限来源 | 控制面编译时确定 | 分级 + 批准阶梯（一次性 → 常驻规则 → 配置白名单） |
| 人的介入点 | 审批与发布环节 | 每次有后果的动作前；无人值守时停靠到收件箱等答复 |
| 变更传播 | 显式重新冻结；**旧快照不续用** | 阶梯每一步**显式、可见、可撤销** |
| 失败姿态 | 权限/版本/治理拒绝 fail closed；可降级项带固定码降级 | 沙箱不可用即拒绝；审查不确定则升级给人 |
| 隔离手段 | 跨语言权限边界 + 票据 | OS 级容器（内核强制 + 网络白名单） |
| 身份留痕 | 冻结身份（版本 + 摘要） | 批准来源（自动/用户/拒绝）+ 审查者推理 + 强制层级 |
| 幂等 | 任务幂等键 + 冻结身份防重 | 未核对 |
| 灵活性 | 低（改策略须重新冻结） | 高（可渐进放权） |
| 确定性 | 高（逐字节可复现） | 中（审查者判断有不确定性） |
| 前置成本 | 高（需完整控制面：编译/版本/账本/发件箱） | 中（需分级表 + 审查者 + 沙箱运行时） |

## 5. 各自的代价（取舍才是重点）

**路径 A 放弃了什么**

- **灵活性**：策略变更要重新冻结，**旧快照不续用**——真实代价是已完成的终态结果
  **不会自动更新**，用户必须重跑任务才能吃到新策略
- **前置能力**：需要一整套控制面（编译、版本、账本、发件箱、门禁），小项目扛不动
- 换来：确定性、可复现、可审计、性能可预期

**路径 B 放弃了什么**

- **延迟与成本**：每个动作都要过裁决，审查者是模型调用
- **审查者的可靠性天花板**：会误判 → 所以需要熔断器兜底；官方文档自己承认
  「判决是判断，不是保证」
- **必须在场**：无人值守时动作只能停靠等人
- **便利性**：沙箱内没共享凭据时 `git push` 直接失败；给运行中的会话加文件夹要**重建沙箱**、
  shell 状态丢失；依赖宿主 OS 能力（Landlock / 容器运行时）
- 换来：能处理事前无法枚举的动作、可渐进放权、单点越界被物理限制

---

## 6. 两条路径收敛出的三条铁律

这才是真正可迁移的部分——**换任何 AI 系统都成立**：

**① 失败关闭（fail closed）**
墙没了就不跑，绝不允许"降级到无保护"。
A 侧：权限/版本/治理拒绝一律不降级。B 侧：沙箱不可用即拒绝会话。

**② 执行侧不可信，权威与密钥不交给它**
A 侧：执行侧不持有权限/主数据权威，只能拿短期票据。
B 侧：沙箱内运行器不持密钥、不做决定，返回的一切当数据。

**③ 身份与来源必须留痕，且按"来源"判定信任，不按"外观"**
A 侧：冻结身份（版本+摘要）+ 运行账本。
B 侧：批准来源 + 审查者推理 + 强制层级，全部落审计。

第 ③ 条里藏着一句可以单独讲的判断：

> **不要问它声称自己是什么，要看它是谁注册的、手上拿到了什么。**
>
> A 侧：不看执行侧自称有什么权限，只看它拿到的票据能开哪扇门。
> B 侧：不看 MCP 工具自称 read，只看它的 `category` 是"第一手目录"还是"陌生人声明"。

## 7. 面试可用的口径（诚实版）

**必须守住的边界**：路径 B 是**公开开源项目研究**，不是本人交付。
任何情况下都不能说"我做过 / 我参与了 / 我们团队做了"那个开源项目。

**安全的讲法结构**（问题 → 两条路 → 取舍 → 铁律 → 我落在哪）：

1. **问题**：让 AI 干活就得给工具和终端，威胁来自"合法能力被误导性使用"，
   所以治理必须是架构而不是插件
2. **两条路**：一条事前冻结契约（我的项目），一条事中分级 + 物理隔离（研究过的开源项目）
3. **取舍**：冻结换来确定性、可复现，代价是灵活性——策略变更要重跑；
   分级换来灵活和渐进放权，代价是裁决成本 + 审查者会误判 + 必须有人在
4. **铁律**：无论哪条路都收敛到三条——失败关闭、执行侧不可信、按来源判信任
5. **我落在哪**：我在自己项目里做的是解析链路治理与长任务可靠性这一侧，
   处理的是"契约不兼容要整体返工""预算合并会出事"这类具体问题

**这条路线的说服力在于**：不吹自己做过什么，而是展示**我理解这个问题的解空间**——
知道有两条正交路径、各自的代价、以及为什么两条路最后收敛到同样的三条铁律。
