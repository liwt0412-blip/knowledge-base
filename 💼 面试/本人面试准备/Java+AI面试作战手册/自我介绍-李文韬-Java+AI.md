## 自我介绍（约 60-75 秒）

面试官好，我叫李文韬，来自湖南长沙，一共六年开发经验，四年半 Java 后端，近一年半专注 AI 应用开发。我所在的是长城信息股份有限公司，这些年按项目制交付过电商中台、同城社交、能源政企经营分析等不同行业的系统，目前岗位是 AI 应用开发工程师。技术栈以 Spring Boot、Spring Cloud Alibaba 为主，Nacos、Gateway、RabbitMQ、RocketMQ、Redis、MyBatis-Plus 都有深度使用；AI 侧以 Spring AI Alibaba 为核心，从 Milvus、Elasticsearch 的混合检索重排，到 MCP 工具治理，都有完整落地经验。

2023 到 2025 年，我在一个能源省公司的经营分析平台做后端，负责设备 IoT 接入与状态监控，后期带 2 人小组；集团推动 AI 落地时，我负责省公司 AI 助手的本地化，把 Function Calling、RAG、缓存、SSE 流式输出接进了真实业务系统，知识检索当时走的是独立的 Python RAG 服务。

那段落地经历让我看到一个共性问题：知识检索、工具调用、会话管理在每个项目里各写各的，跨语言链路维护成本也高。2025 年下半年起，我参与的 AskXBOT 企业级 AI 智能体平台，做的就是把这些能力平台化、统一治理，AI 核心链路基于 Spring AI Alibaba，我在其中负责 Bot 对话与会话记忆、RAG 混合检索、Tool Calling 与 MCP 工具治理三个模块，混合检索把召回率从 78% 提到 92%，关键场景幻觉率压到 2% 以下。相比石化时期，RAG 从 Python 独立服务演进成 Java 侧向量加 BM25 双路召回，工具调用从硬编码 Function 演进成 @Tool、HTTP、MCP 三类工具统一治理。

另外，我是 AI 编程工具的深度使用者，有一套自己和 AI 协作的开发方法论。我的定位是 Java 后端打底、AI 应用开发为方向的工程师，擅长把大模型能力安全、可控地接进企业业务系统，关注权限、成本、延迟和稳定性。AskXBOT 和石化这两条 AI 落地链路我都有完整实战，待会儿可以重点展开。

## 口径要点（备考用，不朗读）

- **"四年半 Java 后端 + 约一年半 AI 应用开发（共六年）"**：与简历 header（6年经验）和自我评价对齐；简历 2026-08 更新后同步的口径，不要再讲"四年+两年"。
- **"长城信息股份有限公司"**：公司全称，被追问公司性质时说明按项目制交付、行业跨度是交付属性。
- **叙事顺序是刻意正序**：石化 → 痛点 → AskXBOT，体现技术演进和做平台化选择的思考，不是跟风；与 AskXBOT 逐字稿 1.1 同口径，开场用哪份都不打架。
- **石化只留四个钩子**：小组长、IoT 状态监控、AI 助手本地化、Python RAG 服务（演进的起点）；集团 AI 底座、Qwen3 等细节留到追问层。
- **AskXBOT 只认领三个模块**：Bot 对话与会话记忆、RAG 混合检索、Tool/MCP 工具治理；Agent Graph、平台级模型管理属团队协作，不主动讲。
- **技术栈句的取舍**：Java 侧 7 个词全部有项目支撑；RocketMQ 与 RabbitMQ 并列是故意埋的追问点；ClickHouse、MongoDB、Netty、Dubbo 不在自我介绍里报，留到项目展开。
- **AI 方法论钩子（不展开）**：只说"有一套方法论"，不讲细节，把追问留给面试官。被问"你的方法论是什么"时切到 [[04-Agent编程与AI工具/AI-Agent辅助开发流程与代码验证面试回答|AI 协作方法论回答]]：哪些环节交给 AI、哪些决策权在我（架构取舍、技术选型、业务口径）、生成代码怎么验证。自我介绍里绝不主动展开，展开就冗长且钩子失效。
- **结尾三钩子**：AskXBOT（开场项目）+ 石化（兜底项目）+ AI 协作方法论（差异化亮点），面试官接哪个都有对应材料。
- **开场第一句固定**：必须以"面试官好，我叫李文韬"开头，第一句内带出总年限（六年开发经验）。回答再精简也不能丢名字和年限。
